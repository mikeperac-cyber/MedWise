# MedWise

_[Türkçe: README.md](README.md)_

A medication guide and dose-tracking app for people who struggle to understand
their own prescriptions. Turkish interface, six independent pages, runs
entirely in the browser.

**What this project is actually trying to do:** the World Health Organization
reports that in developed countries, adherence to long-term therapy for
chronic disease averages around **50%** (WHO, _Adherence to Long-Term
Therapies_, 2003). Part of that non-adherence is not forgetfulness — it is
**not understanding**. The text patients are handed is usually not text a
patient can read. MedWise **measures** that gap first, then tries to close it.

The interface stays in Turkish deliberately. The readability gap being
measured is a property of real Turkish patient-information text, not of an
English mock-up — translating the app would remove the thing being studied.

---

## The measured result

Every number below is computed from the live dataset (`npm run
measure:readability`) — none of it is hand-typed into the code. Two published
Turkish readability formulas are used: **Ateşman (1997)** (0–100, higher =
easier) and **Bezirci-Yılmaz (2010)** (years of schooling required). In
Turkish, every syllable contains exactly one vowel, so syllable counting is
exact, not estimated.

| Text layer                                 | n   | Median Ateşman | Bands                            |
| ------------------------------------------- | --- | -------------- | --------------------------------- |
| Technical descriptions (all)                | 593 | **1.65**       | 558 very hard, 31 hard, 4 medium |
| Technical descriptions (citation-verified)  | 56  | **33.86**      | mostly hard                       |
| **Plain-language layer**                    | 56  | **77.15**      | 44 easy, 7 very easy, 0 hard      |

Implementation: [`src/utils/readability.ts`](src/utils/readability.ts).

**What this measurement does not say:** it shows the text is *readable*. It
does not show a patient *understood* it. Proving that requires a real
comprehension test with real readers. See
[`analysis/CLOZE_PROTOCOL.md`](analysis/CLOZE_PROTOCOL.md) for the protocol
designed to run that test — the protocol exists; the data collection does
not, yet.

## Data provenance warning (important)

**537 of the 593 records** in `public/drugs.json` have ATC, NDC, and TİTCK
(Turkish drug registry) identifiers that are **not real.** These identifiers
were generated by [`scripts/generate_drugs.mjs`](scripts/generate_drugs.mjs),
the script that grew the dataset from 10 records to 593, from a loop counter.
The drug **names** are real; the classification codes are not.

Example: lisinopril is a real ACE inhibitor with the real ATC code
`C09AA03`. The dataset instead says `N02A11` — which is not even a
structurally valid ATC code.

The app does not hide these records. Instead:

- Every monograph opens with a banner stating whether the record is
  verified.
- For unverifiable records, all three identifiers are shown struck through
  and labeled "(generated value)."
- Unverifiable records get **no plain-language summary.** Telling a patient
  "this drug treats X" based on a made-up class code is worse than saying
  nothing.

**The gold set.** Of the 56 records whose ATC code is not just
structurally shaped like a real WHO code but was individually hand-checked
against a real source (the WHO ATC/DDD Index, and where a stable document
existed, an FDA DailyMed label), each carries a citation link and the date it
was checked — see
[`src/data/goldCitations.ts`](src/data/goldCitations.ts). That is a stronger
claim than "looks like the right shape," and it is the only claim in this
dataset backed by an actual document, not a pattern match.

Logic: [`src/utils/provenance.ts`](src/utils/provenance.ts).

## Pages

Six separate HTML documents. Single-page hash routing was removed; each page
has its own URL, its own `<title>`, and its own JavaScript bundle.

| Page               | Path             | What it does                                                                 |
| ------------------- | ---------------- | ----------------------------------------------------------------------------- |
| Dose Cockpit        | `/`              | Today's doses, adherence ring, water tracking, as-needed meds                 |
| Drug Encyclopedia   | `/ansiklopedi`   | Pill appearance first, then a plain-language summary, technical detail last   |
| Cross-Interaction   | `/etkilesim`     | Whether two or more drugs interact                                            |
| Chronobiology       | `/kronobiyoloji` | Which drug works better taken at which time of day                            |
| BYOK AI Lab         | `/yapay-zeka`    | Optional workspace that runs on your own API key                              |
| Academic Portfolio  | `/portfolyo`     | Method, measurements, data audit, clinical cases                              |

### Page architecture

Shared header, footer, and modals live once under `partials/` and are
inlined into every page at build time via a `<!--@include ... -->`
directive (a small [Vite](vite.config.ts) plugin). So the shared UI lives
inside the served HTML — the browser never assembles it afterward.

```
partials/               shared header, footer, modals
src/pages/*.page.html   each page's own content
src/pages/*.ts          each page's entry point (thin)
src/features/           page behaviors
src/shell/              navigation, modals, notifications, BYOK, backup
src/utils/              readability, provenance, plain language, clinical math
```

## About the AI panel

The previous build had a "local clinical synthesis engine" that activated
when no API key was entered. In reality this was a five-branch `if/else`
block keyed on keywords, presented to the user as if it were generated
clinical analysis — including dosing instructions given by the clock.

**It was removed.** Without a key, the panel is now closed and says so
explicitly. There is no fallback engine. With a key, the request goes
directly to whichever provider you chose; the key is stored only in your
browser and never sent to any MedWise server (MedWise has no server). Your
question goes to the provider — using this panel means sending text to that
company.

---

## Privacy

No server, no account, no telemetry. Your dose list and settings live only
in your browser's `localStorage`. You can export and re-import your data as
JSON. The one exception is the BYOK panel described above.

## Setup

Requires Node.js 20+ and npm 9+.

```bash
npm install
npm run dev
```

Open `http://localhost:5173`.

## Tests

96 tests, 7 files. Two are more than ordinary unit tests:

- [`tests/dom.test.ts`](tests/dom.test.ts) — a **per-page DOM contract.**
  Resolves each page's `@include`s, walks that page's import graph, and
  confirms every element the code touches actually exists in that page's
  markup. This is the test that catches the "works on the cockpit, silently
  dead on chronobiology" failure mode introduced by the multi-page split; it
  caught six real bugs during that rebuild.
- [`tests/dataQuality.test.ts`](tests/dataQuality.test.ts) — verifies the
  readability formulas, the provenance classification, and that the
  plain-language layer **refuses** to describe unverifiable records.

## Known limits

- 537 records have fabricated identifiers (see above). The correct fix is
  to hand-verify them one by one against TİTCK KÜB and FDA labels; that has
  not been done.
- The plain-language summaries cover only the 56 citation-verified records.
- The cloze comprehension protocol (`analysis/CLOZE_PROTOCOL.md`) is
  defined but has not been run with real participants — no human
  comprehension claim is made.
- Accessibility was improved (skip link, focus trap, `aria` labels, a
  visible focus ring) but has not been tested end-to-end with a screen
  reader.
